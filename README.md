# Reconciliation Agent — Portfolio Project

An AI agent that parses messy wholesale order-change emails, checks stock and
dispatch status against a mock ERP, and either reconciles the order or asks
for clarification when a product reference is genuinely ambiguous.

**Fictional company, fictional data.** Not built for or with any real
company's data or systems — the distributor and products in `setup_db.py`
are invented.

## Status so far

- [x] `setup_db.py` — mock ERP schema + seed data (SQLite), with two
      deliberately ambiguous product pairs (two keg sizes, two cider
      variants) to test the clarification path
- [x] `agent_config.py` — system prompt + two tool definitions:
      `verify_order_modification` (unambiguous path) and
      `request_clarification` (ambiguous path — the fix for the "what if
      Claude guesses the wrong SKU" gap)
- [x] `agent_engine.py` — orchestration loop: sends the email to Claude,
      routes whichever tool it calls to the matching local logic, gets the
      final customer-facing reply
- [ ] Streamlit dashboard (`app.py`) — not yet built
- [ ] Sample/synthetic test emails, including ambiguous ones generated by
      Claude — not yet built
- [ ] Azure migration (Azure SQL, containerize, Container Apps deploy)

## Design notes worth remembering

The ambiguity-handling design (`request_clarification`) exists because an
enum-constrained tool call will always resolve to *some* SKU even when the
customer's wording was genuinely ambiguous (e.g. "kegs" with two sizes in
stock). Rather than a numeric confidence threshold, the system prompt uses a
hard rule: any genuine ambiguity in the SKU mapping routes to a clarifying
question, never a guess — because a wrong guess ships the wrong product,
which is worse than a short delay.
